# Production Security & Hardening Checklist

- **Verification Branch:** `audit/production-readiness`
- **Last Audited Against Code:** November 8, 2026

## 1. Implemented & Verified Controls

- [x] **Zero Hardcoded Secrets & Fail-Closed Secret Checks:** `GEMINI_API_KEY`, `PAYMOB_HMAC_SECRET`, `ASSET_SIGNING_SECRET`, `SHOTISTRY_ADMIN_BOOTSTRAP_SECRET`, and `DATABASE_URL` are loaded strictly from server environment variables. Paymob webhook fails closed (`503`) if `PAYMOB_HMAC_SECRET` is unset/placeholder; `ASSET_SIGNING_SECRET` (>=16 chars, non-placeholder) throws in `NODE_ENV=production` if unset; `SHOTISTRY_ADMIN_BOOTSTRAP_SECRET` (>=24 chars, non-placeholder) is mandatory for CLI admin bootstrap.
- [x] **Server-Side Key Isolation:** Zero server secrets or database credentials are exposed to Next.js client bundles. AI calls (`@google/genai`) and storage signing run strictly server-side.
- [x] **Database-Backed Opaque Sessions (`Option A`):** Sessions generate 256-bit `crypto.randomBytes(32).toString('base64url')` tokens stored exclusively as SHA-256 `tokenHash` in `"Session"`. Cookies use `HttpOnly`, `SameSite=Lax`, `Path=/`, no `Domain` attribute, explicit `Max-Age`/`Expires`, and `__Host-shotistry_session` + `Secure` in production ([`src/lib/auth/session.ts`](file:///Users/tasawk/StudioProjects/shotistry/src/lib/auth/session.ts)).
- [x] **Full Session Lifecycle & Revocation:** Enforces session rotation (`ROTATED_ON_AUTH`), sliding idle expiration (7d default), absolute expiration (30d default), server-side logout (`LOGOUT`), multi-device listing, single-device revocation (`DELETE /api/auth/sessions/[id]`), bulk revocation (`POST /api/auth/sessions/revoke-all`), workspace switching (`POST /api/workspace/switch`), and automatic full-session invalidation on password change (`PASSWORD_CHANGED`).
- [x] **Cryptographic Password Security & Anti-Enumeration:** Native Node.js 24 Argon2id (`crypto.argon2('argon2id')`, `m=19456`, `t=2`, `p=1`) with asynchronous semaphore concurrency limiter (`SHOTISTRY_MAX_CONCURRENT_HASHES=4`) to prevent serverless OOM, bounded verify, transparent migration from legacy scrypt, `constantTimeDummyVerify` on nonexistent emails, generic `"Invalid email or password"` `401` responses, and `409` duplicate email masking ([`src/lib/auth/password.ts`](file:///Users/tasawk/StudioProjects/shotistry/src/lib/auth/password.ts)).
- [x] **Fail-Closed Distributed Rate Limiting:** Sliding-window rate limiting backed by Upstash Redis REST (`UpstashRateLimitStore`) or PostgreSQL ACID store (`PostgresRateLimitStore`), with client IP extraction honoring trusted proxies (`SHOTISTRY_TRUSTED_PROXY_COUNT`), IPv6 `/64` CIDR grouping, PII-free SHA-256 hashed keys, and fail-closed `503 RATE_LIMITER_UNAVAILABLE` behavior in production ([`src/lib/security/rate-limit/`](file:///Users/tasawk/StudioProjects/shotistry/src/lib/security/rate-limit/)).
- [x] **Transactional Email Transport & Bilingual Templates:** Resend API transport (`ResendEmailTransport`) and in-memory fallback (`MemoryEmailTransport`), rendering strictly sanitized bilingual (`ar`/`en`) RTL/LTR email templates for verification, reset, change confirmation, security notices, and workspace invitations ([`src/lib/email/`](file:///Users/tasawk/StudioProjects/shotistry/src/lib/email/)).
- [x] **Single-Use Action Token Lifecycle (`AuthActionToken`):** Cryptographically random 256-bit action tokens stored as SHA-256 hashes (`tokenHash`) with atomic single-use SQL consumption (`UPDATE ... WHERE consumedAt IS NULL ... RETURNING *`), strict TTLs (24h verification, 15m reset, 1h email change), and `#token=` URL fragment delivery preventing token leakage in server logs or HTTP referrers ([`src/lib/auth/action-tokens.ts`](file:///Users/tasawk/StudioProjects/shotistry/src/lib/auth/action-tokens.ts)).
- [x] **Hardened Account Recovery & Privileged Account Protection:** Anti-enumeration `POST /api/auth/forgot-password` returning uniform `202` with constant-time floor padding (~50 ms); `ADMIN` and `SUPPORT` roles are strictly excluded from email reset (logging `PRIVILEGED_RESET_ATTEMPT` audit records); `POST /api/auth/reset-password` pre-validates and hashes password before token consumption, revokes all sessions (`PASSWORD_RESET`), invalidates all outstanding tokens, clears session cookies, and sends security notices ([`src/app/api/auth/forgot-password/route.ts`](file:///Users/tasawk/StudioProjects/shotistry/src/app/api/auth/forgot-password/route.ts), [`src/app/api/auth/reset-password/route.ts`](file:///Users/tasawk/StudioProjects/shotistry/src/app/api/auth/reset-password/route.ts)).
- [x] **Verified-Email Gating & Identity-Bound Invites (ADR-007):** Commercial checkout, workspace creation, and member invites are strictly gated by `requireVerifiedEmail` (`403 EMAIL_VERIFICATION_REQUIRED`); member invites (`WorkspaceInvite`) require explicit invitation email and strict identity matching (`session.email === invite.invitedEmail`) on accept ([`src/lib/auth/email-verification-guard.ts`](file:///Users/tasawk/StudioProjects/shotistry/src/lib/auth/email-verification-guard.ts), [`src/app/api/workspaces/invites/accept/route.ts`](file:///Users/tasawk/StudioProjects/shotistry/src/app/api/workspaces/invites/accept/route.ts)).
- [x] **Token-Leakage Defense & Security Headers (`next.config.ts`):** Global security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`) and strict `Referrer-Policy: no-referrer` + `Cache-Control: no-store` on all token-handling paths.
- [x] **PostgreSQL 16 & Concurrency CI Gate:** Verified all 21 application tables, `_prisma_migrations`, and 9 enum types across 3 Prisma migrations on real PostgreSQL 16 with ACID concurrency tests covering registrations, trial grants, session logins, rate limiting, and token consumption with zero skips (`npm run test:pg`).
- [x] **Zero Header / Cookie / Client-Role Spoofing:** Forged `x-user-id`, `x-user-role`, `x-workspace-id`, `x-country`, unsigned legacy cookies (`shotistry_*`), and registration JSON `role`/`platformRole` attributes are ignored or rejected (`403`). Unauthenticated requests never default to `ADMIN` and never auto-provision a default workspace or trial credits.
- [x] **Multi-Tier RBAC Separation:** Strictly separates `PlatformRole` (`USER`, `SUPPORT`, `ADMIN`) from per-workspace `WorkspaceRole` (`OWNER`, `ADMIN`, `MEMBER`, `VIEWER`) loaded live from SQL on every request ([`src/lib/auth/rbac.ts`](file:///Users/tasawk/StudioProjects/shotistry/src/lib/auth/rbac.ts)). Workspace `OWNER` holds zero platform permissions; Platform `ADMIN`/`SUPPORT` receive zero implicit bypass on tenant routes (`/api/jobs/[id]`, `/api/workspace/session`, `/api/photoshoots/generate`).
- [x] **Out-of-Band CLI Admin Bootstrap:** Single initial `ADMIN` created strictly via CLI ([`scripts/bootstrap-admin.mjs`](file:///Users/tasawk/StudioProjects/shotistry/scripts/bootstrap-admin.mjs)); zero HTTP admin-signup path exists; fails closed (`ADMIN_ALREADY_BOOTSTRAPPED`) if an admin already exists.
- [x] **Single-Trial Anti-Farming:** `TRIAL_GRANT` (`+5` credits) is atomically granted at most once per `User` via `trialGrantedAt` and `idempotencyKey='trial:grant:user:<userId>'`. Additional workspaces created via `POST /api/workspaces` start with `0` credits.
- [x] **Layered CSRF Defense:** Combines `SameSite=Lax` + `HttpOnly` + `__Host-` production cookies, strict `application/json` checks on auth POSTs (`415`), `Sec-Fetch-Site` + `Origin`/`Referer` verification (`validateSameOrigin`), and timing-safe session-bound `x-csrf-token` validation (`validateCsrfRequest`) on all authenticated state-changing endpoints ([`src/lib/security/csrf.ts`](file:///Users/tasawk/StudioProjects/shotistry/src/lib/security/csrf.ts)).
- [x] **Timing Attack Defense (Webhooks & Secrets):** Paymob HMAC-SHA512 verification, asset download HMAC-SHA256 verification, CSRF hash comparison, password comparison, and admin bootstrap secret comparison all use `crypto.timingSafeEqual()`.
- [x] **SQL Injection Prevention:** 100% parameterized queries via `node:sqlite` prepared statements (`?` bindings) and PostgreSQL Prisma ORM / parameterized `$queryRaw` / `$executeRaw` queries.
- [x] **Input Validation & Secure Upload Gateways:** API inputs validated via Zod schemas and explicit runtime checks. Asset uploads and image generation validate binary headers (`image/png`, `image/jpeg`, `image/webp` via `sharp`), enforce 20MB payload ceilings (`413`), serve downloads via HMAC-SHA256 signed URLs (`3600s` = 1-hour default TTL), and block directory traversal using `fullPath.startsWith(baseDir + path.sep)`.
