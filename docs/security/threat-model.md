# Threat Model & Vulnerability Assessment (STRIDE)

Formal STRIDE threat model aligned with Shotistry's **Option A Session Security**, **Multi-Tier RBAC**, **Credit Ledger**, **AI Pipeline**, and **Paymob Billing** architecture (`audit/production-readiness`).

| Threat Category | Potential Attack Vector | Impact | Implemented Engineering Countermeasure & Residual Risk |
|---|---|---|---|
| **Spoofing (Identity & Cookie)** | Attacker sends forged headers (`x-user-id`, `x-user-role`, `x-workspace-id`), unsigned legacy cookies, or subdomain cookie-tossing payload to impersonate another user or admin | Critical | Auth resolves **only** from SHA-256 hash of `HttpOnly` opaque cookie joined against `"Session"` and `"User"` (`src/lib/auth/session.ts`). Legacy headers and unsigned cookies are ignored. Production enforces `__Host-shotistry_session` (`Secure`, `Path=/`, no `Domain`) and refuses unprefixed cookies. |
| **Spoofing (Credential Stuffing & Enumeration)** | Attacker probes `/api/auth/login` or `/api/auth/register` to harvest valid customer emails or brute-force passwords | High | Native `crypto.argon2('argon2id')` (`m=19456,t=2,p=1`) with concurrency semaphore (`SHOTISTRY_MAX_CONCURRENT_HASHES=4`) + `constantTimeDummyVerify` equalizes timing; login returns generic `401 "Invalid email or password"`; registration returns generic `409`; fail-closed distributed rate limits backed by Upstash Redis or PostgreSQL (`RateLimitBucket`) with client IP extraction and IPv6 `/64` grouping. |
| **Spoofing (Account Recovery & Mailbox Hijacking)** | Attacker probes `/api/auth/forgot-password` to enumerate accounts, or uses email reset on privileged accounts | Critical | Anti-enumeration uniform `202 Accepted` response with constant-time floor padding (~50 ms); standard merchants get single-use 15m `AuthActionToken`; privileged roles (`ADMIN`, `SUPPORT`) receive zero emails and zero tokens, logging an immutable `PRIVILEGED_RESET_ATTEMPT` audit row. Password reset validates strength and pre-hashes before token consumption, atomically revokes **all** active sessions (`PASSWORD_RESET`), invalidates all outstanding tokens, clears session cookies, and sends security notices. |
| **Information Disclosure (Token Leakage via Referrers/Logs)** | Password reset or email verification tokens leak in HTTP access logs, browser history, or Referer headers | High | All tokens are formatted inside URL fragments (`#token=`) which browsers never transmit over HTTP. Client-side pages scrub the fragment via `window.history.replaceState` immediately upon mounting and transmit the token securely in POST JSON bodies. `next.config.ts` enforces `Referrer-Policy: no-referrer` and `Cache-Control: no-store` on all token-bearing routes. |
| **Elevation of Privilege (Workspace Member Impersonation)** | Attacker adds arbitrary users to workspaces without consent, or attacker intercepts invite link meant for another user | High | Replaced instant addition with identity-bound `WorkspaceInvite` and verified-email gating (ADR-007). `POST /api/workspaces/invites/accept` requires authenticated session + CSRF + verified email and strictly checks `session.email === invite.invitedEmail` (`403 INVITE_IDENTITY_MISMATCH` if mismatched, leaving invite unconsumed). Commercial checkout, workspace creation, and member invites are gated by `requireVerifiedEmail`. |
| **Spoofing (Payment Webhooks)** | Attacker spoofs Paymob webhook callbacks to illegally grant credits or activate paid subscriptions | Critical | Fail-closed `PAYMOB_HMAC_SECRET` check (`503` if unset/placeholder), cryptographic HMAC-SHA512 digest check with `crypto.timingSafeEqual` (`401`), and `WebhookEvent` deduplication. Missing or unknown `workspace_id` fails closed (`400`/`404`) without provisioning workspaces. |
| **Tampering (CSRF & State Mutations)** | Malicious site triggers cookie-authenticated `POST`/`DELETE` requests against session, workspace, generation, billing, or admin endpoints | Critical | Four-layer defense (`src/lib/security/csrf.ts`): `HttpOnly` + `SameSite=Lax` cookie, `application/json` pre-auth check (`415`), `Sec-Fetch-Site` + `Origin`/`Referer` check (`validateSameOrigin`), and timing-safe session-bound `x-csrf-token` (`validateCsrfRequest`). |
| **Tampering (AI Prompts & Plan Bypass)** | Merchant requests `gemini-3-pro-image` or `4K` output while on `FREE`/`STARTER` plan, or injects prompt overrides | High | Zod & server-side type sanitization in `PromptSynthesizer`; `validatePlanModelEntitlement()` rejects disallowed models/resolutions (`403`) before credit reservation; credit weights (`1`/`2`/`3`/`4`) computed server-side. |
| **Repudiation** | Merchant or operator denies purchasing credits, generating jobs, adjusting balances, or bootstrapping platform admin | Medium | Immutable append-only `CreditLedger` (with `idempotencyKey`), `PaymentTransaction`, `WebhookEvent`, and `AdminAuditLog` recording `userId`, `operatorRole`, `targetId`, `ipAddress`, and JSON details. |
| **Information Disclosure (Cross-Tenant IDOR & Assets)** | Authenticated merchant supplies another workspace ID in body/URL, views member PII as `VIEWER`/`MEMBER`, guesses `.data/assets` paths, or retrieves old session tokens | Critical | Every protected route enforces `session.activeWorkspaceId` and live `WorkspaceMember` membership (`403` on body `workspaceId` mismatch or cross-workspace `/api/jobs/[id]`). `/members` restricts `GET` to `OWNER`/`ADMIN`. Assets use UUIDv4 keys, HMAC-SHA256 signed URLs (`3600s` = 1h TTL, fail-closed `ASSET_SIGNING_SECRET` in prod), and `baseDir + path.sep` traversal guards. |
| **Denial of Service** | Bot floods upload/generation endpoints with oversized or malformed binaries to exhaust disk, CPU (`sharp`), or Gemini API quota | High | Strict 20MB payload ceiling (`413`), `sharp` image format validation (`422`), auth endpoint rate limiting (`429`), and upfront `SERIALIZABLE` credit reservation (`402` on zero balance). |
| **Elevation of Privilege** | Anonymous caller hits `/admin`, `USER` sends `role: "ADMIN"` on signup, `WS_OWNER` tries to access `/api/admin/*`, `SUPPORT` deducts credits, or `WS_ADMIN` promotes self to `OWNER`/`ADMIN` | Critical | Strict multi-plane RBAC (`src/lib/auth/rbac.ts`): signup forces `role='USER'` and rejects `role`/`platformRole` (`403`); `/api/admin/*` strictly requires `PlatformRole` (`SUPPORT` capped at `+1..+200`, zero negative debits); `WS_OWNER` has zero platform permissions; `WS_ADMIN` cannot call `/billing/checkout-intent` or manage `ADMIN`/`OWNER`; `ADMIN` created only via out-of-band CLI (`SHOTISTRY_ADMIN_BOOTSTRAP_SECRET`). |
